# ML Models — Design, Data & Evaluation

Two lightweight scikit-learn models power early disease-risk detection (NFR4: no deep
learning, small artifacts, CPU inference). Both artifacts and their metrics JSONs are
committed under `backend/services/python/ai-service/app/models/` and regenerable via the
scripts in `backend/services/python/ai-service/training/`.

## Datasets

| Dataset | Source | Size | Used for |
|---|---|---|---|
| Pet Health Symptoms | [HF karenwky/pet-health-symptoms-dataset](https://huggingface.co/datasets/karenwky/pet-health-symptoms-dataset) / [Kaggle yyzz1010](https://www.kaggle.com/datasets/yyzz1010/pet-health-symptoms-dataset) | 2,000 rows | Model A (condition classification) |
| Animal Condition Classification | [Kaggle willianoliveiragibin/animal-condition](https://www.kaggle.com/datasets/willianoliveiragibin/animal-condition) | ~871 rows | Model B (danger probability) |

Dataset 1: free-text symptom descriptions (owner-style and clinical phrasing) labelled with
5 condition categories: **Skin Irritations, Digestive Issues, Parasites, Ear Infections,
Mobility Problems**. Note: the dataset is synthetically generated (Gemini 2.5 Pro) — cited
as a limitation in the thesis.

Dataset 2: `AnimalName`, `symptoms1..5`, `Dangerous` (yes/no).

## Model A — Condition classifier (11 classes)

Class space: the 5 dataset condition categories **plus 6 chronic diseases**
(Chronic Kidney Disease, Diabetes Mellitus, Liver Disease, Heart Disease,
Pancreatitis, Cancer). The chronic classes are trained from 2,700
knowledge-grounded synthetic rows (450/disease) generated by
`training/chronic_synth.py`: each disease's documented clinical sign profile
(e.g. polyuria/polydipsia + weight loss for CKD; weight loss despite normal
appetite for diabetes; nocturnal cough + exercise intolerance + syncope for
cardiac disease; icterus + ascites for hepatic disease; acute vomiting +
abdominal pain for pancreatitis; mass + cachexia for neoplasia) is sampled
with realistic sign probabilities, age ranges, and species priors, then
rendered through the same runtime `payload_to_text` bridge.

Held-out per-class F1 for the chronic diseases is 0.97–1.00. **Honest
caveat for the thesis:** these scores measure how separable the encoded
clinical patterns are — not clinical diagnostic accuracy on real cases,
since the rows are synthetic. Overlapping acute presentations (e.g. severe
vomiting) may legitimately rank Pancreatitis above Digestive Issues — a
clinically defensible differential; the urgency recommendation is identical.

### Original 5-class notes

- Pipeline: `TfidfVectorizer(ngram_range=(1,2), min_df=2, max_features=20000)` →
  `LogisticRegression(max_iter=1000, class_weight="balanced")`.
- **Train/serve bridging:** the app collects *structured* form data, not free text. At
  serve time `feature_bridge.payload_to_text()` renders the form into an owner-style
  sentence; at train time ~500 augmentation rows are generated through the *same*
  templates (`training/train_condition_model.py::build_augmented_rows`), closing the
  distribution gap between the HF free text and rendered form text.
- Split: 80/20 stratified over 2,500 rows (2,000 HF + 500 augmented).
- Results (`condition_metrics.json`): **accuracy 0.826, macro-F1 0.826**; per-class P/R and
  the confusion matrix are in the JSON, plot at `docs/ml/condition_confusion_matrix.png`.
- Explainability: per-prediction top TF-IDF term contributions are returned as
  `top_features` in the API response.

## Model B — Risk (danger) model

- Features: symptoms multi-hot encoded over the 40 most frequent dataset symptom tokens
  (`MultiLabelBinarizer`); bridge tokens are alias-mapped to dataset spellings
  (diarrhea→diarrhoea etc.).
- Model: `LogisticRegression(class_weight="balanced")` wrapped in
  `CalibratedClassifierCV(method="sigmoid", cv=3)`.
- Results (`risk_metrics.json`): ROC-AUC ≈ 0.96, PR-AUC ≈ 0.999, balanced accuracy 0.5 at
  the 0.5 threshold.

### Class-imbalance caveat (important for the thesis)

~97.7% of rows are labelled *dangerous*, so hard-label metrics are meaningless (a
constant "dangerous" classifier gets 97% accuracy; recall on the minority class at the
default threshold is 0). Therefore the system **never uses Model B's hard label**. It
uses the *calibrated probability* as one signal, blended with a deterministic severity
index derived from the reported vitals and duration:

```
severity = 0.7 * mean(vital severities) + 0.3 * min(duration/7, 1)
score    = 0.6 * P(dangerous) + 0.4 * severity
risk     = high (score ≥ 0.66) | medium (≥ 0.40) | low
```

When the form reports **no abnormal signals at all**, Model B is skipped entirely
(P=0): with zero evidence its intercept alone would still lean "dangerous" because of
the training prior — a documented, deliberate guard (`predictor.py`).

ROC-AUC ≈ 0.96 shows the probability *ranks* dangerous vs non-dangerous cases well,
which is exactly the property the blend relies on.

## Runtime behavior

- Artifacts load once at FastAPI startup (`model_store.load_models()`).
- If artifacts are missing/corrupt, `/predict` falls back to the legacy rule heuristics
  and reports `model_version: "rule-fallback"` — the endpoint never 500s.
- Every prediction is persisted to MongoDB (`predictions` collection) for the history
  API and the autonomous monitoring agent; persistence failures are non-fatal.
- Neo4j ontology enrichment (`ontology_links`) explains which reported symptoms
  INDICATE which diseases, with weights.

```bash
cd backend/services/python/ai-service
pip install -r requirements.txt -r training/requirements-train.txt
python training/download_datasets.py

python training/train_risk_model.py
```

service Docker image (train inside `python:3.11-slim` if your local Python differs).
